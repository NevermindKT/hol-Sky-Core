# Зображення в діалогах

Звук друку вибирається за `speaker` репліки: `assets/dialogue_sounds/<speaker>.wav` (також підтримуються `.ogg` і `.mp3`, у цьому порядку). Назва має точно збігатися з ID, наприклад `security.wav`. Якщо відповідного файлу немає, використовується `typing_sound` вузла DialogueText; якщо він не заданий — друк беззвучний. `speaker_sounds_path` і `typing_volume_db` налаштовуються в Inspector. Звук відтворюється лише для літер.

Текст має темну обводку товщиною 5 у `assets/fonts/CormorantTheme.tres`. Для відповідей товщина й колір також доступні у `DefaultDialogueStyle.tres`, разом із `button_texture` та кольорами наведення/натискання. Кнопки розтягуються в контейнері HBox або VBox.

Підсвічування персонажа — вузол `Interface/Character/Glow` із шейдером `CharacterGlow.gdshader`. PNG залишаються без змін. Колір, яскравість і ширину ореолу задають `warm_light`, `cool_light` і `radius` у ShaderMaterial. Обводка тексту також задана безпосередньо на текстових вузлах, щоб окрема сцена не залежала від глобальної теми.

`DialogueSystem.tscn` містить весь інтерфейс і може бути екземпляром будь-якої сцени. Main лише запускає сюжет і обробляє квестові події. Після додавання сцени викликайте `await dialogue.start_dialogue("intro_line1")`; `play(id)` відтворює одну репліку. Сама сцена не запускає сюжет автоматично.

У Inspector задайте `dialogues_path`, `speakers_path` і `visuals_path`. Для цього проєкту вони вже підключені до файлів у `jsons`.

## Формат репліки

```json
"presentation": {
  "environment": "stranger",
  "character": "stranger",
  "emotion": "nervous"
}
```

Зображення застосовуються на початку репліки, перед друком тексту. `speaker` задає ім’я мовця, а `character` — персонажа на екрані: це незалежні поля. Наприклад, під час репліки героя на екрані може залишатися незнайомець.

- `environment` вибирає пару `background` + `footer` з `visuals.json`; обидві текстури завантажуються до оновлення вузлів.
- `character` вибирає персонажа з `visuals.json`.
- `emotion` вибирає текстуру з його `emotions`. Якщо заданий персонаж без емоції, використовується `default_emotion`.
- Пропущене поле зберігає попередній стан. Можна задати лише `emotion` для поточного персонажа.
- `"character": ""` ховає персонажа. `"environment": ""` ховає і фон, і стійку.

У наявних репліках локація та персонаж задані явно, щоб результат не залежав від попередньої гілки чи точки входу. Емоції можна змінювати без редагування скриптів.

`visuals.json` містить локації `guard`, `stranger`, `barman`, `scientist` і персонажів `security`, `stranger`, `barman`, `scientist`. Для нової локації додайте пару ресурсів; для нової емоції — шлях до PNG у словнику `emotions`. Персонажі героя й оповідача не мають окремих зображень у поточних assets.

Зображення зберігаються після завершення діалогу. Для очищення використовуйте `clear_visuals()` або порожні ID в наступній репліці.

## Перевірка

```text
godot --headless --path . --script addons/dialogue_system/validation/ValidateDialogues.gd
```

Валідатор перевіряє переходи, персонажів, емоції та існування текстур. Якщо є помилки, база не завантажується.
